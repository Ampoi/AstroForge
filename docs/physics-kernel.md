# Zig物理カーネル

物理計算の既定バックエンドは `zig-wasm` です。`native/physics.zig` を `wasm32-freestanding` にコンパイルし、Node.js標準のWebAssembly APIから同期的に呼び出します。ネイティブアドオンや追加のnpm実行時依存はありません。[Zig公式のWebAssembly説明](https://ziglang.org/documentation/0.16.0/#WebAssembly)を参照してください。

## 移行した処理

- 位置・速度・姿勢quaternion・角速度の13成分を進める6自由度RK4積分。
- 中心重力、共回転大気に対する速度、標準大気・上層の密度近似。
- 抗力、胴体と安定翼の法線力、空力トルク、剛体の角加速度。

1/120秒の各ステップで、RK4の4回の微分評価をまとめてWasm内で処理します。`f64`、`ReleaseSafe`でビルドし、fast-mathは使いません。燃料消費前の質量をステップ全体で使う順序、各微分評価でのquaternion正規化、積分後の正規化は従来と同じです。

機体構成、質量・慣性の再計算、アクチュエータ配分、燃料・電力、分離・衝突判定、破片の管理、軌道要素、UDP・HTTPはJavaScriptです。120 Hzと時間倍率、外部コントローラの期限、PyLoNパケット形式は維持します。

## ビルドと起動

Node.js 22.12以降と **Zig 0.16.0** が必要です。Zigのバージョンは `.zig-version` で固定しています。

```sh
zig version
npm run build:physics
npm start
```

`npm start` / `npm run dev` / `npm test` / ベンチマークは物理ビルドを先に実行します。ソース・ビルドスクリプト・生成物のハッシュが一致すれば再ビルドを省略するため、同じ生成物の実行にZigは不要です。生成物は `build/physics.wasm`、キャッシュは `.zig-cache/` で、両方ともGit管理対象外です。配布先で `node server/index.js` を実行する場合はWasm生成物を同梱してください。

```sh
ZIG=/path/to/zig npm run build:physics
npm run build:physics -- --force
```

Wasmが存在しない場合やABIが一致しない場合は起動を止め、再ビルドを案内します。自動でJavaScriptへ切り替えることはありません。比較・調査のために参照版を使う場合は明示します。

```sh
# 物理WasmやZigがない環境でも参照版の物理処理を実行可能
# /docs/ の表示が必要なら先に npm run docs:build
ASTROFORGE_PHYSICS=js node server/index.js
ASTROFORGE_PHYSICS=js node tests/benchmark.js
```

現在のバックエンドは起動ログとHTTP/SSEの `connection.physicsBackend` に `zig-wasm` または `js` と表示します。

## メモリ境界

ABIバージョン1は、固定長の `Float64Array` を入出力に使います。入力は状態13成分、質量、重心3成分、慣性9成分、逆慣性9成分、高さ、力3成分、トルク3成分、dtの43要素に、翼ごとの位置3成分・法線3成分・面積の7要素を続けます。最大80翼です。出力は積分後の13成分、または空力の力3成分・トルク3成分・動圧・Mach・迎角・抗力の10要素です。

Wasmのヒープ確保、メモリ拡張、JSへのコールバックはありません。同じインスタンスの作業領域を複数機体で順番に使い、各呼び出しで全入力を設定し、結果をコピーして返します。分離物・破片は親のバックエンドを継承します。将来Worker化する場合はWorkerごとにインスタンスを用意してください。

翼数上限・入力のfinite・出力のfiniteを検査し、積分失敗時は既存の数値異常停止処理で機体を停止させます。

## 検証と性能計測

```sh
npm test
npm run benchmark
npm run benchmark:physics
```

参照版は `server/physics-reference.js` に保持しています。大気の全層境界・150 km境界、姿勢や速度を変えた320ケース、80パーツ、150秒の2段飛行・燃料枯渇・分離物、真空軌道3周、機体間のメモリ独立性、異常値による停止を検証します。飛行比較は毎秒実施し、位置差0.2 mm以内、速度差0.02 mm/s以内を要求します。既存のUDP・HTTP・資源収支・衝突・自動操縦テストも同じ既定Zigバックエンドで実行します。

比較ベンチマークはバックエンドごとに5つの独立プロセスを順序を交互に変えて起動し、2秒分のウォームアップ後、10秒分の物理計算と20 Hzテレメトリ生成を計測します。中央値を報告し、性能をテストの合否条件にはしません。描画・ネットワークI/O・複数機体間の衝突探索は計測に含まれません。

2026-09-23、macOS / Node.js 24.18.0 / Zig 0.16.0での結果です。時間は10シミュレーション秒を処理する実時間です。

| パーツ数 | JavaScript | Zig Wasm | 高速化 |
| --- | ---: | ---: | ---: |
| 13 | 73.5 ms | 35.4 ms | 2.08倍 |
| 80 | 326.3 ms | 105.7 ms | 3.09倍 |

物理ステップのp95の中央値は13パーツで0.094→0.028 ms、80パーツで0.318→0.139 msでした。Wasm生成物は25,763 bytes。Zig版・JavaScript参照版ともに62/62テストが成功しました。これらはこの機体構成・環境での計測値であり、描画FPSや多数機体での高速化率を示すものではありません。
