# 雲の分布・大気の描画負荷

雲は軽量な描画近似です。気象計算とは独立しており、低層の厚み、中層の小さな塊、高層の薄い筋を描き分けます。

| 層 | 設定した高度 | 描画する特徴 |
| --- | --- | --- |
| 低層 | 0.9〜3.0 km | 積雲・層積雲に似た塊、平らな雲底、丸い上面 |
| 中層 | 5.0〜5.7 km | 高積雲に似た小さな塊が広がる薄い層 |
| 高層 | 9.5〜10.5 km | 巻雲に似た透ける細い筋 |

雲の分類と形状は [NWS Cloud Classification](https://www.weather.gov/lmk/cloud_classification) を参考にしています。高度は代表的な描画設定で、実際の雲底高度は緯度や気象条件によって変わります。低層は体積をサンプリングし、中層・高層は各高度帯の中央に置いた薄い球殻で近似します。凝結・降水・対流・雲の生成消滅は計算しません。

## 晴天域とまとまった雲域

湿った空気が上昇して冷え、飽和すると水滴や氷晶ができ、雲になります。上昇の原因には地表加熱による対流、前線、山地などがあります。反対に下降する空気は暖まり、雲ができにくくなります。[NWS の雲の発達の解説](https://www.weather.gov/source/zhu/ZHU_Training_Page/clouds/cloud_development/clouds.htm)を参考にしています。

地球規模では熱帯収束帯、中緯度の低気圧・前線に雲が集まり、亜熱帯の下降流域では晴れ間が広がります。ただし、冷たい海面の上では下降流域でも低い層積雲が広がることがあります。[NASA の全球雲分布の解説](https://science.nasa.gov/earth/earth-observatory/cloudy-earth-85843/)と [NASA GISS の大気循環と雲の解説](https://www.giss.nasa.gov/research/briefs/2017_tselioudis_02/)を参考にしています。NASA の月平均図は気候的な傾向であり、その模様を一日の雲として貼り付けてはいません。

この特徴から、次の合成天候図を事前生成しています。

- 水分・上昇・下降の強さに相当する無次元の値で、広い晴天域と雲域を分けます。
- 熱帯は蛇行し途切れる雲帯、中緯度は曲がった前線と低気圧の雲域、亜熱帯は広い晴れ間を作ります。
- 大陸形状のデータで陸海を区別し、西岸沖の低い海上雲を陸上に延ばさないようにします。
- 低層・中層・高層は同じ天候図を参照します。前線や対流域では複数の高度に雲がつながり、海上の低い雲域では主に低層だけが現れます。
- 発射場（経度・緯度ともに0度）の周囲は、通常のフライト画面から低層雲を見られる合成天候にしています。雲域は周囲へ滑らかに減衰し、他地域の晴天域を維持します。通常画面とマップは同じ天候図を参照します。
- マップでは地域の雲量を残し、近づくと体積ノイズによる個々の雲の形に切り替えます。高層の模様も地域の雲域内に限定します。

これは実際の形成条件を参考にした**固定の合成スナップショット**です。気圧・水蒸気・温度の流体計算、山岳性の上昇流、季節変化、時間による天候の発達、実際の現在の天気は再現していません。全天を「晴れ／曇り」に一括切替するのではなく、同時に異なる天候の地域を持ちます。

## ゲームの雲描画から取り入れた手法

[Guerrilla Games の Nubis（SIGGRAPH 2017）](https://www.guerrilla-games.com/read/nubis-authoring-real-time-volumetric-cloudscapes-with-the-decima-engine)は、天候による雲量・雲種の制御、大きな形状、小さな輪郭の侵食を分離しています。Perlin-Worley などのノイズを単に掛け合わせず、値の範囲を再割当てして削ることで、雲の中心の密度を残します。今回の実装では次の形で応用しています。

- 天候図の座標を複数の大きさで歪め、緯度に沿った帯や同じ形の低気圧が並ぶ印象を弱めます。前線内の細部は、その前線の曲がりに沿って引き伸ばします。
- 滑らかな値ノイズと反転した Worley 型のセル模様を組み合わせ、雲域内に丸い塊と切れ目を作ります。輪郭を削る際は密な中心を残します。この処理は天候図の生成時に行います。
- 近景用の3D形状にも同じセル模様による侵食を焼き込み、密度と法線を1回のテクスチャ参照で取得します。追加の詳細ノイズを毎サンプル計算する必要はありません。
- 天候図の雲種に応じて低層の高さ方向の密度分布を変え、海上の浅い雲層と対流域の厚い雲を描き分けます。
- 遠景では画素より細かい3D模様の参照を省き、フィルター済みの天候図を使います。

[Unreal Engine の実装解説](https://dev.epicgames.com/documentation/en-us/unreal-engine/volumetric-cloud-component-in-unreal-engine)も、低解像度での描画と再構成、雲のない領域での高価な評価の省略、ライティングの近似を挙げています。本実装も描画先の画素数とサンプル数を制限し、晴天域を早期に省略します。時間方向の再投影や追加の光線探索は使わず、視点変更時の追従と現在の描画予算を維持します。

## 負荷を抑える仕組み

- 天候図の配布データは128×128 RGBAの6面キューブマップ（384 KiB）で、読み込み後にWorkerで512×512へ高精細化します（GPU上はミップ込み約8 MiB）。球面の向きから直接参照し、経緯度変換の計算と極域で模様が放射状に伸びる問題を避けます。広域の天候分布の生成は開発時の `npm run build:weather` で行い、実行時は同梱の `public/assets/cloud-weather.rgba` を一度読み込みます。毎フレームの気象計算や定期通信はありません。
- 雲の形状ノイズ・セル模様による侵食と陰影用の法線を起動時に一度生成します。元データは64³ RGBA、1 MiBです。今回のローカル計測では生成に約86 msで、フレーム描画中には再生成しません。
- 晴天域では雲の形状・陰影サンプリングを省略します。地表テクスチャも球面上の画素サイズでフィルターを選び、日付変更線の点線状の継ぎ目を防ぎます。
- 各視線サンプルから再び太陽方向へ探索する処理を廃止し、事前生成した情報で陰影を近似します。
- 低層は球殻の各区間を4点で調べ、中層・高層は球殻との交点だけで評価します。
- 飛行・マップの両方で、雲を含む背景の描画先を各辺35%、最大16万画素に制限します。高DPIでも雲の計算量が増え続けません。
- 合成時に地球の深度を画面解像度で復元し、軌道線の遮蔽を保ちます。機体・発射場は画面解像度で描画します。

この予算では遠景の色や雲の細部が柔らかくなります。雲の自己遮蔽と地表への雲影は近似です。

## 固定シードによる高精細化

2026-09-27追加。細部は毎フレーム計算せず、生成・読み込み時に焼き込みます。AIによる元画像の復元ではなく、元の形を保つ手続き的な細部の追加です。

- **陸地**: 2048×1024から4096×2048へ変更。従来の地形モデルから2Kの元画像を作り、経度の折り返しに対応した補間で拡大してから、固定シード `73129` の球面ノイズを2段階で色に加えます。海の色にはノイズを加えず、標高用alphaは補間だけに留めます。物理用の標高・衝突計算は従来どおりです。処理全体を地形Workerで実行します。
- **雲**: 同梱の128×128×6面を読み込んでから、Workerで512×512×6面へ補間し、同じ固定シードで部分的な雲域の輪郭に細部を加えます。補間は隣接する面まで参照し、細部は球面座標で評価するので新しい面境界を作りません。晴天・完全な被覆・雲種のチャンネルを保ちます。近距離用64³体積ノイズとレイのサンプル数は従来どおりです。
- **星空**: 大きな星空画像を廃止し、固定シード `411` の5,000個の星を画面解像度で1回の描画にまとめます。小さな明るい中心と柔らかな周囲を点の中で計算し、拡大画像のぼけを避けます。背景の透過率を参照して雲・惑星・昼の空による遮蔽を保ちます。実在の星表ではありません。
- **合成**: 従来の追加ぼかしを、近傍の最小・最大値を超えない弱いシャープ化に置換しました。地平線や雲の端に明るい縁を増やさず、低解像度の背景を復元します。地表と重なる雲の遮蔽境界も、深度4点の手動補間で滑らかにします。整数深度テクスチャのハードウェア線形フィルターには依存せず、近い機体が雲に隠れない精度を維持します。

雲・大気は各辺35%、最大16万画素、低層各区間4サンプルを維持します。シャープ化は背景色参照5回、飛行時の深度補間は4回、星は追加1 draw callです。地形の初回生成とテクスチャ転送は増えますが、生成中も仮テクスチャで描画を続けます。GPUテクスチャの概算は、地表・天候・旧星空の合計約54 MiBから約51 MiBへ（ミップ込み、星の頂点約137 KiBを含む）。初回生成中のCPU一時バッファは別です。フレーム時間はGPUと視点に依存するため、以下のベンチマークで確認します。

## PyLoNのパーツモデル

2D/3D LiDAR、RGBカメラ、スタートラッカー、回転サーボ、直動モーターの表示には、PyLoNのMITライセンスのモデルを使用します。メッシュ、法線、刻印、単色テクスチャの配色を取り込み、ブラウザ用の索引付きジオメトリとして同梱しています。通常のビルド・起動にPyLoNやBlenderは不要です。

取付方向とサイズはAstroForgeのパーツ定義へ合わせています。直動モーターは元モデルの縦横比を保って外径0.40 mへ一様に拡大し、収納時の全長は約2.054 mです。接続位置もこの全長に合わせています。サーボのローターはZ軸ヒンジとして回転し、直動モーターの可動段は既存の0〜2 mの伸縮量へ表示を合わせます。これは外観の再利用で、PyLoN側の質量、制御仕様、衝突メッシュは移植しません。センサー観測とUDPのURDFには従来の近似形状を使用します。

変換手順・元ファイルのハッシュ・ライセンスは`src/assets/pylon/README.md`と`THIRD_PARTY_NOTICES.md`を参照してください。`tests/pylon-models.html`はVite開発サーバーで6種類の外観と関節表示を確認するページです。

### マップと追尾カメラの共通化（2026-09-27）

太陽系マップの地球は従来、地表だけの `MeshStandardMaterial` で描かれ、追尾側の雲・大気の描画を通っていませんでした。`SolarMap` に同じ `EarthEnvironment` を渡し、天候キューブ・3D雲形状・照明・地表・大気・描画予算を共有します。マップのカメラを浮動原点から地球中心へ平行移動し、自転分だけ地球固定座標へ戻して描きます。出力した地表深度を月・機体・軌道の描画でも使い、従来の地球メッシュによる上書きを止めています。遠い注視対象でも球との交差判定が桁落ちしにくいよう、光線の最近接距離を使います。

全球を表示する宇宙シミュレーター [Celestia の地球設定](https://github.com/CelestiaProject/CelestiaContent/blob/master/data/solarsys.ssc)では、地表とは別に `CloudMap` と `CloudHeight` を指定しています。このように惑星座標に固定した全球の雲分布を持つ設計と、上記の [Nubis の雲域・形状・細部を分ける手法](https://www.guerrilla-games.com/read/nubis-authoring-real-time-volumetric-cloudscapes-with-the-decima-engine)を参考にしています。外部の画像やコードは取り込んでいません。

分布は数百km規模のまとまりを強め、細かいノイズの寄与と乾燥域の雲を減らしました。前線の密な中心と海上雲は残します。発射場中心の低層雲量の設定値は約0.74から約0.39へ下げ、近景の3D形状の空間スケールは2倍にしました。これは天候図の値と形状の設定であり、画面で白く見える面積の測定値ではありません。

`tests/map-clouds.test.js` は地球・月・太陽・機体への注視切替と時刻変更後の視線、投影位置、深度、描画順序を確認します。`tests/weather.test.js` は隣接する雲域の連続性、晴れ間、発射場の雲量も確認します。WebGLの回帰確認には `/tests/map-clouds.html` を追加しました。1280×720／509×717で本番の `SolarMap` を描き、雲あり／なしの差、同一視点の追尾側とのRGB差、手前／地球の裏側の物体の遮蔽を測定します。`/tests/flight-clouds.html` は発射場の空が雲で埋まりすぎない上限も確認します。
