## 流体としての扱いと限界

噴射直後の発光ガスと、大気に巻き込まれた低温の混合後流を別に扱います。

- 発光ガスは実際のノズル出口・ジンバル軸を中心とする連続した軸対称の密度場です。螺旋配置の明るい粒を炎として描く方式を廃止しました。
- 半径は出口から増加し、断面積の増加に応じて密度を `r_exit² / r(z)²` で薄めます。これは軸方向速度を一定とした連続の式の近似です。発光は冷却を表す減衰を掛けます。
- 大気が薄いほど膨張角を大きくします。真空でも噴射は続きますが、大気に巻き込まれた煙は消えます。機体の軌道速度を架空の向かい風として扱いません。
- 発光領域は地面との交点で積算を止めます。混合後流は既存の慣性座標のWasm流れモデルで大気に追随し、地面・機体との接触で進路を変えます。描画用の流れから機体へ力は返しません。
- 混合後流の粒子は、広がるほど投影面積に反比例して光学的な濃さが減ります。粒子の間引きでは光学重みを補償します。

**これは検証済みのCFD・燃焼計算ではありません。** 機体定義には推力と比推力があり、燃焼室圧・ノズル出口圧・温度・燃料組成はありません。したがって膨張角・発光長・色・冷却率は定性的な可視化近似です。現在の大気入力も高度から求める相対密度で、ノズル圧力比ではありません。密度から正確な圧力比を求めたとは扱いません。

[NASAの推力式](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/rocket-thrust-equation/)では、推力は質量流量・出口速度・出口圧と周囲圧の差に依存します。比推力だけでこれらを一意に決定できないため、ショックダイヤモンド・過膨張による剥離・マッハディスクは推測して追加していません。[NASAのプルームと地面の相互作用](https://www.nasa.gov/directorates/stmd/plume-surface-interaction-psi/)のような圧縮性流れ・衝撃波・土壌飛散を再現するモデルでもありません。

発光する近傍噴流は準定常・直線軸として扱います。急激な姿勢変化の履歴、近傍の横風偏向、ノズル同士の噴流干渉、ガスの化学反応、局所の固体との相互作用や複雑な地形面への衝突は解いていません。地面のクリップは機体直下の接平面です。機体と透明体積の交差では深度プロキシによる近似誤差があり得ます。

## 軽量化

- 最大80噴射源を一つのインスタンス描画にまとめます。噴射源ごとに箱12三角形、ピクセルごとに円錐と視線の交差区間を求め、固定12サンプルだけ積算します。広い境界箱全体を積算してノズル付近に帯が発生することを避けます。画面全体のレイマーチ、3D流体格子、テクスチャ、追加照明、影、追加レンダーターゲットは使用しません。
- ガス場は半径だけで定義するため、横・斜め・軸方向の視点でも中心がずれず、中空の筒になりません。
- 煙は既存の最大2,400個の計算用パーセルから、生成シードで安定して約1/3を選び、描画を最大800個に制限します。若いパーセルは描きません。選んだ分だけソート・転送し、片面分の一回のパスで描きます。
- 真空では混合後流の計算・ソート・描画を省略します。
- 停止・機体切替・巻戻しで古い噴射インスタンスを残しません。

```sh
npm test
npx vite --host 127.0.0.1
# 表示されたポートの /tests/exhaust.html を開く
```

検証画面では大気中・真空・地面への衝突・横風・ジンバル・4エンジン、スロットル、横／斜め／軸方向視点を選べます。Benchmarkは960×540、DPR 1、60ウォームアップ＋120測定フレームです。排気更新のCPU時間とWebGL描画のGPUタイマーを分離し、拡張がない場合はGPU値をnullとします。機体・地面を含み、雲・大気描画を含まない局所テストなので、アプリ全体のFPSを表すものではありません。

## 計測記録（2026-09-26）

macOS arm64 / Node v24.18.0 / Codex内蔵ブラウザー。Wasmバックエンド、上記の固定解像度・同一検証シーンで比較。変更前は `5a9a520` の `src/exhaust.ts`（Git blob）を保存して同じページに読み込ませました。ViteのHMRを無効にして、並行作業の更新による計測中の再読み込みを防ぎました。GPU値は `EXT_disjoint_timer_query_webgl2` によるWebGL描画時間です。

| 場面 | CPU中央値 変更前→後 | GPU中央値 変更前→後 | 描画呼び出し 変更前→後 |
| --- | --- | --- | --- |
| 大気中・1基 | 1.60→1.10 ms | 5.82→2.75 ms | 6→7 |
| 真空・1基 | 0.60→0.10 ms | 2.36→0.49 ms | 6→6 |
| 地面への衝突・1基 | 1.50→1.10 ms | 7.86→4.88 ms | 7→8 |
| 大気中・4基 | 0.70→1.40 ms | 5.57→3.15 ms | 6→7 |

連続噴流のため描画呼び出しは大気中で1回増えますが、煙の重なり・三角形・ソート対象が減り、GPU時間は全ケースで短縮しました。ブラウザーCPU時間は別プロセスの影響などでばらつき、4基ケースではこの測定で増加しました。計測は専有端末での統計的な性能保証ではなく参考値です。大きく拡大した噴流や80基で画面を覆う最悪条件は未計測で、全体FPSの改善率とは区別します。

`Validate pixels` はGPUから256×256の描画結果を読み返します。大気中の横視点で左右差0、真空の横視点・大気中の軸視点では総RGB値に対する左右差0.013%未満でした。真空の軸上輝度が下流へ滑らかに減衰すること、停止時の発光0、地面より下の発光0も成功しました。大気中・真空・ジンバル・軸方向・地面の画面確認、シェーダーコンパイルエラー0も確認しています。

`npm test` の型検査・Wasmビルド・UIビルドは成功。180テスト中171件がサンドボックス内で成功し、ポートのlisten/bind制限（EPERM）で失敗した9件は、ローカル通信が許可された実行で対象4ファイルを再実行して全11件成功しました。したがって180件すべての成功を確認しています。ROS2デモ・bridgeへの変更はありません。

ブラウザーCPU値のばらつきを切り分けるため、同じWasmとカメラ・フレームを使い、描画を含まない `ExhaustEffect.update` もNodeで比較しました。各実装300フレームのウォームアップ後、500更新×9バッチを変更前／後の順番を交互にして測定した中央値です。大気中0.482→0.254 ms、真空0.180→0.0007 ms、地面0.495→0.280 ms、4基0.606→0.320 msでした。この補助測定では全ケースのCPU処理時間が短縮しています。GPU値とは合算せず、ブラウザー実測のばらつきも残して報告します。
