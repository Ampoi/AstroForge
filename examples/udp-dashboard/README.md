# UDP Command Desk

AstroForgeとは別ポート・別プロセスで動く、UDP指令を送るためのダッシュボードです。本体のサーバー・UI・APIを変更せず、内部モジュールやHTTP APIにもアクセスしません。本体を起動しなくても、任意のUDP受信プログラムにJSONを送信できます。

```sh
# 本体は別ターミナルで必要に応じて起動
npm start

# デモ専用のターミナル
npm run demo:dashboard
```

デモ画面: http://localhost:3018/ 。本体の標準ポートは3000です。デモ用のHTTPポートだけを変更する場合:

```sh
UDP_DASHBOARD_PORT=3020 npm run demo:dashboard
```

1. 送信先ホスト、コマンド送信先ポート、テレメトリ受信ポートを入力し「UDP接続を開く」を押します。AstroForge側でUDPをONにした機体のポートを指定してください。受信は127.0.0.1にbindします。
2. UDPセッションを受信したら「制御権を取得」。取得したleaseの自動更新は接続前のチェックボックスで選べます。自動点火・自動姿勢制御はありません。
3. エンジン・切り離し・RCSは対象の`name`を直接入力します。manifestがあれば入力候補を表示しますが、候補外の名前も送れます。機体の形状、段数、ID、アクチュエータのavailable状態によって送信を制限しません。
4. エンジン出力スライダーはN単位の要求推力です。上限も自由に設定できます。「スライダー変更時に送信」がONなら動かすと送信、OFFなら「UDP指令を送信」で送ります。機体能力からの割合計算は行いません。
5. 通常は1回送信。期限内の指令を継続する場合は「20 Hzで連続送信」をチェックしてから送信します。連続送信できる指令は同時に1種類です。別のタブに切り替えただけでは停止しません。「連続送信を停止」で止めます。
6. 切り離しは入力したnameに`separate:true`を1回送信します。対象を自動選択せず、点火や推力変更も追加しません。他の指令が連続送信中なら、必要に応じて先に停止してください。
7. 姿勢入力・RCS・body wrenchもフォームから送れます。「任意のJSON」ではbatchを含む完全なパケットをそのまま送信できます。raw送信ではセッション・sequenceも自動補完しません。

TXは送信完了であり、受理の保証ではありません。受理・拒否と機体の挙動はUDPの受信側が決めます。RXログの`reason`と受信テレメトリで確認してください。

セッションを受信できない環境では「セッションJSONを直接設定」から共通情報5項目を入力できます。raw JSONの送信にはセッションもmanifestも不要です。受信側のホスト・コマンドポートから来たデータだけを受信表示します。

切断・デモ終了・ブラウザとの接続断（3秒）では連続送信を止め、自分が取得中のleaseをUDPで解放します。UDP受信が1.5秒途絶えた場合も連続送信を止めます。セッション変更・取得した制御権の喪失でも停止し、自動で再取得・再点火はしません。設定とUDP接続はこのデモサーバーを開いたブラウザ間で共有されます。

同じテレメトリポートを外部デモや他のUDP受信アプリと同時にはbindできません。HTTPサーバーはループバックにのみbindし、同一originのリクエストだけを受け付けます。

## 独立したテスト

```sh
node --import tsx --test tests/udp-dashboard.test.js
```

テストはUDPの受信役を用意し、本体を起動せずに実パケットを確認します。
